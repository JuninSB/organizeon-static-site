# D4: e-mail OrganizeOn

Publicado em https://organizeon.com.br/d4/ — sessão anônima redireciona a `/d4/login`; conta autorizada no login volta a `/d4/`. Páginas internas por hash. Login e conta existentes, acesso de ultra admin ou superior, sidebar/perfil/DMs e componentes compartilhados.

Fonte do serviço, Worker, implantação, testes e manual: [services/d4/README.md](../services/d4/README.md). Frontend modular: `ui/src/d4/`. Build separado: `ui/vite.d4.config.ts`, saída `d4-dist/`. Alterações mínimas do backend principal estão documentadas em `services/d4/deploy/backend-integration.patch` e `gateway.mjs`; cópia completa de recuperação em `server-backup/organizeon-backend-source.tar.gz`.

## Operação

```
~/organizeon/d4/d4.sh status
~/organizeon/d4/d4.sh start
~/organizeon/d4/d4.sh stop
~/organizeon/d4/d4.sh restart
~/organizeon/d4/d4.sh logs
```

Criar endereços na página Endereços antes de usá-los em cadastros. Não há SMTP aberto ao público: somente usuários autenticados podem solicitar envio; ingestão de mensagens exige assinatura do Worker. Em Configurações, cada conta pode escolher Cloudflare SMTP, SMTP direto ou relay externo; senhas não voltam ao navegador.

## IMAP: requisito de entrada pública (estado atual)

IMAP não está habilitado nesta versão. O D4 atual mantém mensagens e anexos em SQLite, não oferece servidor IMAP e não possui senhas IMAP por endereço. A integração deve usar hashes de senhas exclusivos, desligada por padrão, UID/UIDVALIDITY persistentes, sincronização bidirecional de pastas/flags e revogação de sessões após desativação/alteração de senha. Não expor hashes ou aceitar a senha OrganizeOn como senha de aplicativo.

Antes da publicação externa, é indispensável uma entrada TCP IMAPS com certificado válido, normalmente porta 993: relay/VPS acessível ou IPv6 público alcançável. Cloudflare Tunnel para TCP exige cloudflared no cliente e não substitui essa entrada para aplicativos IMAP comuns. Não anunciar um hostname ou checkbox funcional antes de validar o serviço real e seu acesso externo. Documentação: https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/protocols/

Investigação de 17/11/2026: a API confirmou plano `Free Website`; consulta de aplicativos Spectrum retornou 403. Não foi identificado relay TCP público. O pacote Dovecot não está disponível nos índices APT atuais do Android. O acesso LAN SSH expirou; o acesso remoto funcionou com cloudflared Linux ARM64 forçado para IPv4. Nenhum servidor IMAP, porta pública, credencial IMAP ou mudança de banco foi implantado nesta etapa. A pergunta sobre VPS/relay público permanece pendente.
