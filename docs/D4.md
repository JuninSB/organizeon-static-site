# D4: e-mail OrganizeOn

Publicado em https://organizeon.com.br/d4/ — sessão anônima redireciona a `/d4/login`; conta autorizada no login volta a `/d4/`. Páginas internas por hash. Login e conta existentes, acesso de ultra admin ou superior, sidebar/perfil/DMs e componentes compartilhados.

Fonte do serviço, Worker, implantação, testes e manual: [services/d4/README.md](../services/d4/README.md). Frontend modular: `ui/src/d4/`. Build separado: `ui/vite.d4.config.ts`, saída `d4-dist/`. Alterações mínimas do backend principal estão documentadas em `services/d4/deploy/backend-integration.patch` e `gateway.mjs`; cópia completa de recuperação em `server-backup/organizeon-backend-source.tar.gz`.

- Serviço `organizeon-d4`, Python 3.14 no venv, dnspython 2.9.2; escuta somente localhost:8340. Supervisionado pelo runit iniciado pelo Termux:Boot existente. Não houve reboot para testar boot físico.

- Não há limite artificial de número de caixas por conta autorizada. Disco disponível e cotas do plano Cloudflare se aplicam. Recebimento até 20 MB; anexos de saída até 10 MB no total.

## Evidência de funcionamento

- Sete testes de backend passaram localmente e no Android: isolamento entre contas, endereços reservados, MIME/anexos, deduplicação, rascunhos, cabeçalhos, referências de resposta e erro SMTP fora de Enviados.
- TypeScript e build D4 passaram. Fluxo de navegador no domínio real passou: redirecionamento autenticado, navegação, configurações, criar/excluir endereço vazio e salvar rascunho, mobile 390px e desktop 1365px, sem pageerror ou overflow horizontal. Screenshots inspecionadas. Não houve teste em celular físico.
- APIs sem sessão e ingestão sem HMAC retornaram 401. Conta de cargo admin recebeu 403 para caixas. Sessões curtas de diagnóstico foram criadas exclusivamente em arquivos privados, sem mudança de senha/cargo ou revogação das sessões reais.
- Mensagem externa real enviada via conta Gmail conectada para a própria caixa `organizeon@organizeon.com.br` chegou ao D4: confirma MX → Email Routing → Worker → Tunnel → SQLite. Mensagem de teste permanece identificada na entrada.
- SMTP Cloudflare conectou por TLS na porta 465 e autenticou, mas rejeitou o remetente com `550 5.7.1 Email sending is not enabled for domain organizeon.com.br`. A tentativa real com anexo ficou em Falhas de envio, nunca em Enviados. A permissão da API agora funciona; habilitação do domínio para saída é uma etapa diferente do Email Routing.
- Porta 25 no Android: MX Google falhou com OSError e MX Microsoft expirou por timeout; não houve conexão SMTP direta bem-sucedida. O motor de entrega direta existe e SMTP externo é configurável por conta com STARTTLS ou TLS. Para completar saída, habilitar domínio em Compute → Email Service → Email Sending → Onboard Domain ou configurar relay que autorize @organizeon.com.br.
- D2 e D3 continuaram respondendo, Survival e tmux Xiaomi permaneceram ativos. Serviço D4 observou aproximadamente 20 MB RSS durante os testes, CPU baixa. Nenhuma solicitação de autorização Xiaomi foi enviada.

## Operação

```
~/organizeon/d4/d4.sh status
~/organizeon/d4/d4.sh start
~/organizeon/d4/d4.sh stop
~/organizeon/d4/d4.sh restart
~/organizeon/d4/d4.sh logs
```

Criar endereços na página Endereços antes de usá-los em cadastros. Não há SMTP aberto ao público: somente usuários autenticados podem solicitar envio; ingestão de mensagens exige assinatura do Worker. Em Configurações, cada conta pode escolher Cloudflare SMTP, SMTP direto ou relay externo; senhas não voltam ao navegador.

## Correção do login anônimo

O gateway redirecionava `/d4` corretamente, mas o serviço Python verificava identidade de usuário antes de servir também `/d4/login` e assets, produzindo JSON 401 no navegador. A verificação foi movida para o bloco de APIs; a credencial interna gateway→serviço continua obrigatória, e as APIs de e-mail continuam protegidas. Publicação somente do serviço D4, com rollback do arquivo anterior no diretório privado existente.

Adicionados dois testes HTTP com sessão de usuário ausente e um teste de navegador com contexto sem cookies: login/JavaScript disponíveis, formulário renderizado e caixas postais retornando 401. Os nove testes de backend passaram; a página pública de login respondeu 200.
